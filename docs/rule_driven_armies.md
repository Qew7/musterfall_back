# Правила, состав армии и дробные залпы

## Единый источник для найма и расстановки

`Sim::ArmyComposition` больше не содержит имён abilities или таблицы пар.
Он автоматически опрашивает модули из `Sim::Battle::Rules::REGISTRY`:

- `army_role(profile)` возвращает предпочтительную роль или nil;
- `army_synergies` возвращает массив `Sim::ArmySynergy`.

Один модуль, зарегистрированный в нескольких фазах, учитывается один раз.
Новый отряд с уже поддерживаемыми правилами подхватывается автоматически.
Новое правило, добавленное в боевой реестр и предоставляющее эти методы,
также не требует изменений бота или геометрии.

Ruby-код и текст описания не анализируются для угадывания смысла: для нового
типа взаимодействия автор правила описывает его условия рядом с реализацией.
Это интерфейс правила, а не отдельная таблица настроек бота. Для индивидуальных
правил без зависимости от союзников создавать фиктивную связку не нужно.

### Контракт ArmySynergy

Все предикаты принимают нормализованный профиль: kind, abilities, боевые статы,
models. Для нанятых отрядов models учитывает текущее здоровье.

| Поле | Значение |
| --- | --- |
| consumer | Предикат получателя эффекта |
| provider | Предикат источника поддержки |
| demand | Сколько поддержки нужно получателю; по умолчанию 1 |
| capacity | Сколько поддержки даёт источник |
| range | Радиус размещения относительно источника |
| center_distance | true для расстояния между центрами, иначе между подставками |
| required | Снижать ли привлекательность получателя без доступного партнёра |
| benefit | Дополнительная проверка пользы конкретной пары |

Используй общие константы/предикаты с боевой реализацией, когда это реальные
условия эффекта. Планировочные допущения обозначай отдельно.
Не выполняй запросы в БД или пробные бои из этих методов.

Примеры текущих правил:

- Катапульта использует те же предикаты потребителя/расходника и `FODDER_RANGE`,
  что и её боевое снабжение. Потребность — один расходник на раунд, ёмкость —
  оставшиеся модели поставщика. При шести раундах 15 гоблинов покрывают две
  катапульты; потрёпанного отряда из одного гоблина уже недостаточно.
- Наездник помогает `ferocious`. Поддержка двух отрядов — оценка для найма,
  близкое размещение — подготовка к совместному бою. Реальное условие требует
  фланговой/тыловой атаки по общему противнику; радиуса ауры у этого правила нет.
- `muster` использует мораль источника как радиус и поддерживает только отряды
  с меньшей моралью. Номинальная ёмкость не ограничена числом отрядов, но
  реальное покрытие ограничено геометрией. Найм пока не решает задачу покрытия
  нескольких далёких групп разными героями.

Подбор остаётся эвристическим: он меняет вероятности, учитывая уже набранный
состав, дубли, доступные покупки и деньги. Это не поиск математически лучшей
армии. Расстановка ищет законные позиции партнёров; совместные манёвры в бою
и автоматическое присоединение героев к отрядам не добавлены.

## Дроби только внутри залпа

Common/volley сохраняют дробные значения отдельных попаданий, складывают
успешные попадания по одной цели, применяют её множитель (включая 0.65
для второй цели volley), затем округляют итог вниз: 2.65 → 2 HP урона.
Остаток отбрасывается, не переносится между целями, атаками или раундами.
Залпы на 0.8, 0.8 и 0.8 каждый наносят ноль, а не два суммарных HP.

В бою хранится общее здоровье отряда, а не массив HP отдельных моделей.
Для отряда моделей с 1 HP два нанесённых HP означают две убитые модели;
оставшиеся здоровы. Для многоздоровых моделей сохраняется обычный учёт
целых ран через общее HP. Дробных ран нет.

Каждая атака переднего ряда делает свой бросок; залп применяется одним
действием на цель. В action хранятся реально снятые целые HP, hits_landed
и attacks_attempted. after_hit! вызывается один раз на успешный залп:
эффект попадания вроде toxin может сработать даже при нулевых целых потерях HP.

AI считает математическое ожидание уже округлённого вниз урона по возможному
числу попаданий, E[floor(урон)], а не floor(E[урон]). Например, при двух
атаках с вероятностью попадания 0.5 и уроном 0.6 шанс нанести 1 HP равен 0.25.
Оценка 0.25 не означает, что цель получит дробную рану.

Геометрические шаблоны, ближний бой и магия сохраняют прежний расчёт.
Существующий тип float в balance_counters оставлен для совместимости с
уже записанными результатами предыдущего эксперимента; он не задаёт механику HP.
Старые журналы не переписываются. Цены development-каталога не пересчитывались.

### Исправление прежнего анализа

Старый common поднимал результат базовой формулы до минимума 1 на попадание.
Поэтому утверждение от 18 сентября о нулевом фактическом уроне обычных слабых
стрелков было неполным. Текущий вариант убирает минимум 1 и округляет вниз
только суммарный залп. Промежуточная реализация с сохранением дробного HP
отменена после уточнения пользователя.

Тесты проверяют суммирование внутри залпа, отсутствие переноса остатка,
отдельное округление второй цели и согласованность оценки AI. Исходные армии
и seed пяти сохранённых сценариев сохранены, ожидаемые результаты обновлены
под целые потери HP. Это регрессионная проверка, а не исследование баланса.
